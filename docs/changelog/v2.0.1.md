## 新功能

- hipy/php 源代理新增 toBytes=3 语义：服务端内联流式 pipe（与 /mediaProxy?stream=1 同实现，Range/206/空闲断开语义一致），配合 toBytes=2 重定向，hipy/php 源可稳定代理数 GB、1 小时以上的媒体资源
- /proxy 路由向源注入框架保留参数 `__range`（客户端 Range 头）与 `__mediaProxy`（流式代理基址），py/php 源首次具备感知 Range 与服务端流式出口的能力
- py 基类新增 `proxy_media_url` / `rewrite_m3u8_to_proxy` 辅助方法，php 基类新增 `proxyMediaUrl`：m3u8 改写与直链大文件场景源侧一行接入，`__mediaProxy` 未注入时优雅降级直连
- 桥接单包上限与超时支持环境变量覆写：`BRIDGE_PACKET_MAX`（默认 Node 10MB / 守护进程 60MB）、`BRIDGE_TIMEOUT`（默认 30s），不配置则行为不变
- 全能代理新增自身回环链路支持与 `unified_proxy_self_redirect` 开关（后台「环境配置 → 代理设置」）：默认 0 服务端回环转发，1 时 302 直连自身内容接口（零转发开销、单层代理链）

## 修复

- 修复 php 源调用超时后遗留孤儿进程的问题：execFile 增加 timeout（API_TIMEOUT+5s）超时 kill
- 修复 php 基类 localProxy 默认返回 null 导致 /proxy 空代理 500 的问题（现返回 404）
- withTimeout 超时放弃后，输家 promise 的延迟 rejection（php 被 kill、bridge 延迟超时等）不再触发 unhandledRejection，一处收敛全部调用点
- 修复源 m3u8 重写地址指向本服务 /proxy 时，被 /unified-proxy SSRF 防护按内网地址误拦 403 导致无法播放的问题（自身引用识别放行；172. 私网段判定精确化为 172.16-172.31）
- 修复路由参数 schema 类型过严的壳子兼容回归：/api/:module 的 filter/quick/pg 恢复字符串语义并容纳任意附加参数，/parse/:jx 去掉 url required（此前 TVBox 壳子传 filter=true、空 pg 被 400 拒绝）
- 修复 package-clean 打包脚本遗漏 README 引用文档的问题：新增 docs 引用闭包收集，README 关联跳转随包分发

## 优化

- hipy 引擎清理约 140 行死代码与死常量（两个从未被调用的旧桥接函数），log 本地化消除对全局注入副作用的隐式依赖
- php 引擎清理永假的 SitesMap 空壳逻辑与无关的 PYTHONIOENCODING
- hipy/php/xbpq 模块缓存统一 LRU 化（max 200 / ttl 10 分钟），与 catvod 同口径
- 约 60 个框架文件的 console 输出统一收口至 utils/log.js（util.format 等价格式化 + pino 分级日志），浏览器内联脚本与第三方单文件库除外
- 协议文档补齐：t4api.md 新增「代理接口与 toBytes 协议」章节（五元组语义、长视频三类场景指引、py/php 源写法示例与反模式提示）
